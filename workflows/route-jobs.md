# /route-jobs — intake to Application Pool proposal

Read [execution rules](../rules/search-execution.md) and [contracts](../schemas/search-execution.md). Use the existing source, eligibility, global market, quality and calibration rules.

1. Accept a plain portable JobCandidateBatch, `/scan-jobs` review packets, and optional current pool. Preserve raw records; validate identity, provenance, market, exact authority scope/date, JD and critical unknowns. Exact-role continuity packets must reuse the existing pool entry rather than minting a duplicate candidate. Use UNKNOWN/VERIFY instead of guessed metadata.
2. Deduplicate only exact, officially bound identities. Keep every discovery and authority observation; never overwrite official closure with newer platform content. Ambiguous identity/payload conflicts remain separate and IDENTITY_VERIFY.
3. Before formal routing, bind a task-local candidate context with `new_ssot=false`, provenance, date, scope and evidence refs. If Evidence Fit, Experience Fit, candidate-side Eligibility and strongest evidence are broadly missing, retain identity/dedupe and job-side intake but set `routing_state=PRELIMINARY_CONTEXT_REQUIRED`, `TARGETED_ACTIVE=0` and `FAST_APPLY=0`. Light screen grounded candidates across the existing ten independent dimensions plus Job Quality and work-right friction. Explain claims using duties/evidence, not title/brand/city or percentage. Keep defensible stretch and unsupported scope explicit. Do not do full company research for every result.
4. Propose TARGETED_PREPARE, FAST_APPLY, WATCH_VERIFY or SKIP with lane, reason and exactly one next Human action. For UK roles separate current work right, current residence, required work territory, residence timing, overseas remote permission, relocation feasibility, work-right at the required location/start date, permanent-right requirement, explicit no-sponsorship, future sponsorship need, employer sponsor capability and exact-role sponsorship. Current right PASS with only future sponsorship UNKNOWN may remain FAST_READY with long-term VERIFY risks; current residence outside the UK is not automatic failure, but material territory uncertainty is Watch and cannot start expensive materials without Human acceptance. Unknown current right remains Watch. Quality negatives materially downgrade; dated salary alone never decides. Unknown routine quality fields do not block every role; material missing facts do.
5. Check pool duplicates and company-specific slots. Restore still-relevant Human-reviewed entries missing from the latest batch into a continuity comparison; distinguish NEEDS_REVALIDATION from CLOSED. Absence from a new search is not closure. Apply adjustable Targeted WIP only to high-effort preparation; a high-value excess role stays TARGETED_CANDIDATE / QUEUED. Opportunity/Application Pool and Fast Lane remain wider. Pool entry ordering is a visible allocation input, not a ranking score.
6. Hand selected Targeted roles to /analyse-job → /prepare-application. Fast continues through Quick Screen → Qualification Gate → Light Evidence Match → Base CV Router → optional light tailoring → Human Review → single submission; it does not require full /analyse-job for every reasonable role. FAST_APPLY is a lane label, not submission authorization. Intake lifecycle, route and application status remain separate.

Use intake_batch and route_pool in the [helper](../scripts/search_execution.py) for structured reviewed inputs. LIVE requires actual current source inspection; fixture mode must explicitly say synthetic simulation. Historical rows cannot bypass the existing Core preparation gate. No owner records are modified by this workflow.
