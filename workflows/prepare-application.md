# /prepare-application

1. Read the same-identity JobAnalysis, source revision, relevant existing evidence and current Job Record. If absent, execute bounded /analyse-job first. Recheck changed/stale sources; historical fixture analysis cannot authorize live preparation.
2. Pass the preparation gate: identified real role, authoritative current OPEN status, all applicable hard qualifications ELIGIBLE, evidence-backed reason for preparation, no known contradictory critical information. For a one-active-application company, existing slot must be clear or belong to this exact role; UNKNOWN/occupied other role blocks active tailoring. For UK roles, material territory/residence uncertainty (including relocation or required-location start-date work right) also yields `PREPARATION_HOLD` unless Human explicitly accepts proceeding; confirmed inability to satisfy the required territory remains blocked. Blocked output is `PREPARATION_HOLD` plus reasons/VERIFY actions, no CV claims or packet.
3. Select one proportionate Fast/Targeted strategy based on reviewed analysis. Recommend the existing CV Base and version/reference, select a small project router from allowed evidence, and state why this role. Do not require a full cover-letter/interview/HTML package. If interview preparation is in scope, follow [interview preparation methods](../rules/interview-preparation.md) rather than creating a second preparation workflow.
4. Identify strongest evidence, likely recruiter concerns (INFERENCE), gaps and honest responses. Create only claims with a complete requirement → evidence → verified fact → claim chain. UNKNOWN permission/source links produce gaps; preserve them rather than improving the wording into a fact.
5. Offer relevant portfolio references subject to public-use permission. Prepare evidence stories and second-/third-layer follow-ups with answer boundaries. A proposed metrics framework is a future method, never a past result.
6. Only if the target triggers it and completed evidence is available, create the optional packet under [claim rules](../rules/cv-claims.md). Preserve all missing fields and aggregate-vs-event trace limits.
7. Return ApplicationBrief candidate, checklist and VERIFY items using [contracts](../schemas/contracts.md). For repetitive application-form work, apply [career tooling boundaries](../rules/career-tooling.md): any future prefill tool remains prefill → Human check → Human submit, with sensitive decision fields never submitted unchecked. Stop before material adoption, canonical Save, login, submission, contact, upload or external action. End with `HUMAN_REVIEW_REQUIRED`; this is not approval.

Core Integration: apply [stretch policy](../rules/stretch.md) for strongest truthful wording and internal L1–L3 defensibility. Only when explicitly requested for historical integration review, a HOLD brief may add separate NOT_FOR_ADOPTION framing_review comparisons; claim_candidates remains empty and no packet is generated. Live gates and default HOLD behavior are unchanged.

Job Quality v0.1.1: apply [job-quality rules](../rules/job-quality.md). Carry known serious pay/workload/manager/stability/probation concerns into the brief before further effort. Ordinary UNKNOWN job-quality items alone do not block preparation; preserve existing gates and avoid offer negotiation.

Global Market v0.1.2: follow [global-market rules](../rules/global-market.md). Worthwhile sponsorship-VERIFY roles can receive STRATEGY_ONLY with explicit qualification/work-right uncertainty and unchanged HOLD; confirmed unavailable sponsorship with no other route stops full materials.

Carry decision-relevant [calibration concerns](../rules/market-calibration.md) into bounded preparation; no new factual claims, readiness bypass or negotiation automation.
